# User + Trip Logging Implementation Playbook

## Purpose
Use this as the mandatory implementation checklist whenever code changes user, profile, or trip behavior.

## Canonical model
- `trip_versions.data` is the canonical **snapshot** history.
- `trip_user_events` / `profile_user_events` are compact timeline events.
- `timeline_diff_v1` is the active write format for trip update diffs.
- Legacy `timeline_diff` is deprecated and must neither be written nor read by new code.

## Required write paths
- Profile updates:
  - Write `profile.updated` into `profile_user_events` with before/after data and `metadata.changed_fields`.
- Trip lifecycle updates:
  - `trip.created`, `trip.updated`, `trip.archived`, `trip.share_created` in `trip_user_events`.
  - Include immutable envelope fields on every write:
    - `event_schema_version`
    - `event_id`
    - `event_kind`
    - `correlation_id`
    - `causation_id`
    - `source_surface`
  - Use deterministic conventions where available (`trip-upsert-*`, `trip-version-*`) and preserve caller correlation IDs on archive flows.
- Trip version commits (`dbCreateTripVersion`):
  - Write `trip.updated` with:
    - `timeline_diff_v1`
    - `version_id` + `previous_version_id`
    - `secondary_action_codes`
    - `correlation_id`
- Failures:
  - Persist action failures (`trip.archive_failed` and generic failures) via DB functions into `profile_user_events`.

## `timeline_diff_v1` checklist
- Required keys:
  - `schema = "timeline_diff_v1"`
  - `version = 1`
  - `counts`
  - `deleted_items`, `added_items`, `updated_items`, `transport_mode_changes`, `visual_changes`
  - `truncated`
- Visual-only commits must still emit `timeline_diff_v1` with `visual_changes`.

## Secondary action facet checklist
- Write `metadata.secondary_action_codes` for `trip.updated` events.
- Keep values typed and stable (for example `trip.transport.updated`, `trip.activity.deleted`, `trip.segment.deleted`).
- Keep primary action compact (`trip.updated`); use secondary facets for filter/detail UIs.

## Admin rendering requirements
The **Audit log** screen (`/admin/audit`, `pages/AdminAuditPage.tsx`) merges `admin_audit_logs` and the
user change logs into one timeline. Keep these guarantees when you touch it:

- User/admin timelines must read `timeline_diff_v1` only.
- Table rows show a **compact change summary** (the first two changed fields as `Field: before → after`,
  then "+N more fields"). Use the typed value formatters for structured timeline items — no raw JSON
  blobs in table rows. Clicking the summary opens the entry sheet (`AdminDetailSheet`), which lists
  every changed field, the actor, the raw action code (with copy), the target and the event id.
- "Show full diff" (row `…` menu and entry sheet footer) opens `AdminJsonDiffModal` and must resolve the
  snapshot compare from `trip_versions` when version IDs exist.
- Action, target and facet badges carry their raw code in `data-tooltip`; there is no separate legend.
- Admin audit must support replay export (`admin_forensics_replay_v1`) using the currently filtered timeline rows, preserving event envelope metadata and correlation groups.
- Replay exports must be generated by the server endpoint `/api/internal/admin/audit/replay-export` and each export must persist an `admin.audit.export` entry in `admin_audit_logs`.
- Replay exports must support all three scopes, each reachable from the screen:
  - full filtered export — the "Export replay" page action,
  - selected-row export — "Export replay" in the selection bar (`AdminSelectionBar`), which appears only while rows are selected,
  - single-row export — "Export entry" in the row `…` menu and the entry sheet (`source:id` row keys).
- An action filter that covers every action is stored as "no filter" (`[]`), so actions that appear
  later (wider time range, reload) are never hidden by a stale explicit list.
- Admin audit undo actions must remain append-only:
  - use admin RPCs (`admin_update_trip`, `admin_override_trip_commit`, `admin_update_user_profile`) to create a new audited revert operation,
  - never mutate or delete historical event rows,
  - offer undo only where `canUndoTimelineEntry` allows it (row `…` menu, last item; entry sheet footer), always behind a confirm dialog.
- Undo rows that originate from trip rollback commits must carry source-event linkage metadata (for example `Audit undo <event_id>` label or explicit source id) so admin UI can resolve and render inverted fine-grained diff rows.
- Preferred undo linkage metadata contract for new writes:
  - `undo_source_event_id` (direct reverted event id),
  - `undo_root_source_event_id` (original root user-change event id),
  - `undo_parity` (0/1 parity relative to root event; 1 means inverted view).
- Keep `public.admin_get_user_change_log(uuid)` available and granted; admin audit uses it to resolve source events that are outside the currently loaded timeline window.
- User and trip targets open in an `AdminDetailSheet` that links on to the full record
  (`/admin/users?user=<id>&drawer=user`, `/admin/trips?trip=<id>&drawer=trip`); restore of a
  soft-deleted user stays available in the user sheet footer.
