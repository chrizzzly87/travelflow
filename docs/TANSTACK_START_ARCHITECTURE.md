# TanStack Start architecture and contribution guide

This is the architecture of the TanStack migration branch. It does not claim that the
migration has reached production. Track acceptance, preview and benchmark evidence in
[the migration plan](architecture/TANSTACK_START_MIGRATION.md) and GitHub issue #559.
The earlier Preact reports describe historical releases.

## Runtime and compatibility

Production and component tests use React/React DOM 19.3.1, matching React type
definitions, Start 1.169.2 and Router 1.170.44. These are the newest compatible
releases admitted by the repository's seven-day dependency release-age policy
on 2026-10-22; do not bypass that policy for newer patch releases.
The native `StartClient` owns hydration; do not manually hydrate a
second router or patch React/TanStack internals. React 18 produced intermittent
recoverable errors during selective-SSR startup. The React 19 candidate passes
the unchanged seven affected WebKit scenarios repeated three times.
Use the supported `fetchPriority` image prop and nullable ref types. Keep existing
ref forwarding where Radix or measured elements require it. Testing Library's
`reactStrictMode: true` exercises effect replay at the root, matching the app.

Vaul uses its React-19-compatible release. The existing admin chart package still
declares a React-18-only peer range; its actual bar, area, donut and interactive
list components have an unmocked React 19 compatibility test. This bounded evidence
does not constitute upstream React 19 support. Replacing that dependency is a
separate follow-up ([#584](https://github.com/chrizzzly87/travelflow/issues/584));
do not hide the peer warning with an override.

The synchronous boot script sets the initial theme before paint. `ThemeColor`
claims its immutable document snapshot during hydration, then subscribes to the
shared theme store. React exclusively owns later theme-color metadata changes;
the store owns the document class and browser listeners. Do not mutate a
React-owned meta element from the store: React 19 metadata hoisting can otherwise
retain a stale element alongside the replacement during navigation.

## Ownership, from document to feature

| Layer | Owns | Keep out |
| --- | --- | --- |
| `src/router.tsx` | Native router, request context, search codec, intent preload and scroll restoration | Account state, trip persistence, page registries |
| `src/virtualRoutes.ts` | One native route graph, pathless area layouts, optional locale parameters | A second runtime route interpreter or copies for every locale |
| `src/routes/__root.tsx` | HTML document, native head metadata, request locale and shared application composition | Planner/admin business logic |
| `app/shell/ApplicationShell.tsx` | Auth/dialog providers, shared banners, analytics and opt-in capabilities | Trip editing state, generation state, admin page imports |
| `src/routes/areas/*` | Rendering/access policy and lifecycle boundary for each area | Large page implementations |
| `src/routes/{public,auth,account,admin,trips,create,library}/*` | Native leaf route and page composition | Shared mutable session singletons |
| `features/trips/*` | Trip session, creation, persistence and view preference hooks | Global ownership by the document or marketing shell |
| `features/auth/*` | Route access, session transitions, terms policy and account preferences | Client credentials that grant privileged server access |

`src/routeTree.gen.ts` is generated by the router plugin. Edit the virtual route graph
and its actual route modules, then let the plugin regenerate it. Route helpers in
`config/routes.ts` build canonical URLs and choose namespaces; they do not replace
native route matching.

## Rendering policy

- Public marketing/legal pages render through Start SSR. Seven public entry pages
  in all active locales are prerendered from `app/routing/publicPrerender.ts` through
  the native `pages` configuration. Flat output (`autoSubfolderIndex: false`) emits
  `features.html` and `de/features.html`, preserving slashless canonical URLs.
  Other valid public routes can render on demand; absence of a static file does
  not mean absence of server-rendered content. Never expand the public allowlist by
  crawling account links. `pnpm prerender:validate` checks every emitted locale,
  direction, canonical URL and heading, rejects competing directory indexes, and
  verifies the separate offline shell.
- Auth, account, admin, creation, library and trip workspace areas currently declare
  `ssr: false`. Their browser session and local trip storage are not serialized into
  a public server response. The root still supplies the document and safe metadata.
- `ssr: false` is a rendering decision. Account/admin `beforeLoad` guards and backend
  authorization remain separate requirements. Share-token and owner/editor checks
  remain in the trip loading/persistence services.
- The root must stay safe to execute concurrently for different users and locales.
  Never read browser storage during SSR or put request-specific data in a module
  singleton.

The native root component owns the HTML document, shared providers and application
shell. Stable charset, viewport, theme colour and pre-paint scripts precede
`HeadContent`; native route metadata remains in `head`. Keep the first hydration
head identical to the transported document. A masked offline entry invalidates
only the native root after hydration to resolve the actual URL through `beforeLoad`.
React does not guarantee that suppressed attribute mismatches will be patched;
substituting actual metadata before the first hydration can leave stale canonical links.
Authentication may clear an already presented private workspace during session
replacement, but must not replace pending native route boundaries during hydration.
Use the match's presentation status and an established auth result rather than
the requested URL alone. Initial session discovery must retain the native boundary.
Pending marketing chrome uses `HydrationLocaleBoundary`: a request-scoped,
immutable delivered i18n instance for that initial pending presentation. The
actual route uses the live instance. A later browser-only pending presentation
starts with the live instance. `PendingDocumentLocaleContext` also supplies the
same display locale to navigation, footer and language notices: reading a localized
requested URL while hydrating the English neutral shell would otherwise change
text and insert a notice before hydration finishes. It does not change native route
matching, the actual location or login/action destinations. react-i18next's external-store hydration snapshot reads the current
language, so `startTransition(changeLanguage)` alone cannot prevent a still
pending English document from reading a newly restored German preference.

A future feature can adopt server loaders when its data/access contract supports it.
Do not enable private SSR simply to eliminate a client loading state: first define
server session validation, authorization, cache policy and hydration data boundaries.

## Navigation and loading

The client entry renders native `StartClient` inside the React hydration root.
Let its native Await boundary own asynchronous router restoration. Do not await
`hydrateStart` before creating the React root: its completion signal then runs
outside React's document hydration lifetime. Service-worker registration retains
its separate after-paint/idle scheduling.

Use TanStack route `beforeLoad`, `loader`, `head`, error/not-found handling and layouts
at the layer that owns the behavior. Keep page modules small and delegate domain work
to feature hooks or services with narrow inputs.

Explicitly split route loaders and pending components as well as page/error modules
through `codeSplittingOptions.defaultBehavior`. The plugin defaults do not split
loaders. Verify the emitted module-preload graph: a small route definition that
statically imports a loader can otherwise pull trip persistence into landing pages.

The router uses native intent preloading. Use a native Link or the existing
`app/navigation.tsx` adapter for legacy URL/state call sites. Prefer the native router
API for new route-aware code. Do not add a BrowserRouter, HistoryRouter, descriptor
interpreter, manually imported deferred route table, or a second global prefetch graph.
Before removing an old warmup, verify which domain resource it warmed: route chunks
belong to the router; an expensive map SDK still needs an explicit feature decision.

The search codec preserves repeated query values and existing plain-string URL
contracts. Changing it requires navigation regressions for query, hash, history state
and back/forward behavior.

## Landing pages and first interaction

Render meaningful public content on the server with stable initial geometry. Keep the
hero, example previews and footer independent of idle callbacks or first interaction.
Use lightweight preview data instead of importing full editable itineraries into a
landing page. Load maps, editing tools and account-only capabilities in their owners.

The root imports one shared Tailwind stylesheet. Multiple independent atomic CSS
builds can reorder responsive utilities (for example `.hidden` after breakpoint
rules) and silently hide navigation controls. Feature-specific third-party styles
can remain lazy.

Server output and the first client render must agree. Use `useHydrated` or a scoped
client-only boundary for a genuinely browser-dependent widget. Do not hide complete
marketing sections behind a mount effect to mask a mismatch. Retain the early click
handoff only while production browser tests prove its role before hydration; Start
routing does not make an unhydrated DOM handle React events automatically.

### Appearance and browser preferences

`src/document/theme-boot.js` sets the root theme before paint. CSS selects initial
colours, theme icons and the resting window shade. `contexts/theme/themeStore.ts`
then exposes one stable snapshot of both preference and resolved theme through
`useSyncExternalStore`, sharing OS and cross-tab subscriptions. A system preference
change must update React controls as well as the document class. Browser storage
failure must not erase a choice already made in the current document. Only the
optional WebGL enhancement needs a client effect; decorative static markup does not.

## Auth and feature lifecycle

Account/admin route guards return native redirects with a safe, localized return URL.
`AuthRoutingBoundary` invalidates guards when identity/role/status changes, owns terms
routing, and revokes disabled accounts. Account-specific capabilities load only when
needed. Backend RLS, RPC permission checks and endpoint authorization remain authoritative.

Public navigation uses the same translated Account entry before and after hydration. Browser hints must never fabricate a Session, authenticated status, role or access capabilities. Verified auth updates use transitions where needed to preserve unfinished hydration; keep production browser tests sensitive to recoverable hydration errors. Static public HTML contains no personalized identity.

Async account/profile responses are generation-checked across logout, account changes
and unmount. Never let an old request restore an earlier account's access. Persist
language changes from the i18n subscription; session arrival must not overwrite a
saved preference.

`TripWorkspaceLayout` scopes the editing session by route identity. Persistence,
creation and view preferences have separate hooks. Keep their ownership explicit when
moving remaining TripView logic; avoid replacing one large App file with one large
layout. Admin remains a separate area with its own access boundary and native leaves.

## Locale and metadata

Each server router creates its own i18next instance. Route namespace preloading uses
that instance; browser navigation uses the browser instance. A hover preload must not
change the visible page language. Validate optional locale prefixes and keep canonical
slugs English-only. See [the locale workflow](I18N_PAGE_WORKFLOW.md).

Native `head` metadata is emitted with the document. Generic metadata and locale
come from a fresh native `beforeLoad` document snapshot on ordinary loads and warm
navigation. Root `context` supplies a separate initial URL snapshot only for
masked SPA hydration, where transported `beforeLoad` data still describes the
neutral offline mask. A shared selector owns both native head and document locale;
never rely on cached root route context to refresh on warm navigation. Async
`beforeLoad` also resolves optional public trip metadata and clears it on other
routes. Document locale synchronization restores the selected route language when
the delivered offline shell contains English resources. Site metadata uses the shared
resolver; trip/share summaries cross a validated server-function boundary. Credentials
stay on the server, metadata reads expose only public share-backed summaries, and a
metadata failure must not prevent offline trip access. Do not postprocess the rendered
head through legacy HTML-rewriting edge middleware.

## Build, verification and rollout

See [Netlify deployment](NETLIFY_TANSTACK_START.md) for output and routing ownership and
[the testing scope](TESTING_PHASE2_SCOPE.md) for behavioral acceptance. The service
worker consumes Start's generated offline shell after the build; that shell is an
offline fallback, not a blanket replacement for server routes.

A foundation is not complete because it compiles. Require production browser checks
for first interaction, localized/deep links, auth return, create trip, trip/share/example
lifecycle, admin access, offline recovery, and before/after performance using the same
method. Keep results and limitations attached to the exact revision. Merge migration
work into its integration branch until the preview and acceptance evidence support a
separate production rollout.

## Pending navigation and consent interactions

Native navigation keeps the previous route until the pending threshold (500 ms);
this threshold does not delay a route that is already ready. Marketing pending UI
reuses the real header/footer with working links and a small progress line. Do not
restore fabricated navigation skeletons or an auth spinner/disabled Login control.
The public Account trigger is permanent. Its lightweight guest/member navigation is
eager and uses the already delivered common namespace; opening a verified member
menu must not replace a temporary fallback or wait for profile translations. Full
account, planner and admin workspaces remain split by their native route boundaries.
Guest and unresolved menus retain working actions, including a safe Login URL with
the original path, search and fragment.

The mobile navigation portals into the document body to escape header stacking
contexts. Its account dropdown and language listbox portal into that navigation
dialog so nested focus handling and Escape remain correct. Consent stays above
ordinary page chrome and below modal navigation; it must not block account actions
while its decision remains unanswered.

Any navigation rendered in the SSR fallback must belong to the initial module graph. Do not put that chrome behind an additional manual React.lazy boundary:
Start can activate a client-only route before the nested fallback finishes
hydrating. Keep optional account tools and business workspaces split separately.

Primary hero text and actions render immediately. Decorative entrance animations
must not start essential content at zero opacity or move the intended first target.
Inspect real Lighthouse LCP candidates before claiming an improvement. Desktop-only hero artwork uses native `<picture>` media selection with an inline transparent fallback for hidden mobile layouts. Keep the desktop source in SSR and test viewport changes with scripts held; CSS visibility alone does not prevent an image download.

Undecided consent is part of the server document from its first visible frame. A small synchronous head script reads the existing consent key, and CSS hides an already answered banner before paint. Never defer this banner until interaction or a timer. Its buttons use the shared boot bridge, so a choice made before hydration is replayed once when handlers are ready. Exercise both initial visibility and returning visitors with application JavaScript delayed.

Consent controls subscribe to same-page and cross-tab choices. Analytics checks
consent both before downloading its script and after the asynchronous download,
so withdrawing consent cancels a pending send. Storage keys/categories are unchanged.

Session-sensitive route areas/loaders declare `staticData: { sessionBound: true }`.
The native lifecycle follows parent metadata rather than duplicating URL lists.
On a settled identity/role/status/anonymous-binding change, retire sensitive caches
and preloads. Reload only if a current/pending route is session-bound. Loading flags
or token refresh alone must not invalidate public page work. Preserve immediate
logout/account clears; publish initial session/profile results in a transition so
unfinished route hydration can complete.

### Anonymous visitor session handoff

A first anonymous browser session resolves its capabilities in the background.
It must not re-enter account loading and unmount an already interactive planner
or creation wizard. Access remains empty until bound capabilities resolve; no
member/admin authority is inferred from the anonymous session. Replacement of
an existing identity still clears its capabilities and blocks account loading.
The regression covers preserved input DOM identity, edited draft text and an
open dialog, plus the member-to-anonymous privacy case. Native protected-route
guards and backend authorization remain independently enforced.

### Document-owned translation hydration

Native router dehydration snapshots only the request’s active/fallback language
and loaded namespaces. Hydration restores them before React mounts. The browser
singleton initializes synchronously with no eager namespace fetch, and the client
entry delegates directly to `hydrateStart()`. Initial translations therefore do
not require another dynamic module request outside the router’s error ownership.
Subsequent route transitions still preload their own namespaces in `beforeLoad`;
optional features own their extra resources. Test initial navigation with the
wizard translation module permanently blocked, plus locale/RTL and offline entry.
See `app/routing/localeHydration.ts` for the encapsulated snapshot boundary and
[TanStack’s critical hydration hooks](https://tanstack.com/router/latest/docs/guide/external-data-loading).

The delivered language remains stable for the first hydration render. An unprefixed
workspace then restores its existing browser preference through the document’s
external-state effect, after its required namespaces load. Persistence belongs to
that document subscription, not module initialization; stale preference loads cannot
overwrite a newer language choice or navigation. Blocked browser-storage getters
are treated as unavailable rather than throwing through initialization.

## Framework references and project choices

- [TanStack Start authentication](https://tanstack.com/start/latest/docs/framework/react/guide/authentication): route guards improve navigation; each private data/API boundary must still authorize the request.
- [React external-store contract](https://react.dev/reference/react/useSyncExternalStore): browser preference stores need cached snapshots and a deterministic server snapshot. The pre-paint theme/consent scripts handle browser-only presentation without changing initial React markup.
- [Supabase server-side auth guidance](https://supabase.com/docs/guides/auth/server-side/advanced-guide): verified identity and correct cache boundaries matter. This migration retains the existing Supabase authentication provider and backend permission model; it does not introduce a parallel custom session system.

Public prerenders are visitor-independent. A stable Account entry is deliberate:
member identity and capabilities appear only after verification, without pretending
that a static response knows a visitor's session. If private account rendering later
moves to request-specific SSR, transport verified request-owned auth context through
native route hooks and keep those responses out of shared caches. Never implement
personalization by fabricating a session from a local presentation hint.


## Optional trip generation and claim recovery

Trip viewing imports synchronous retry policy and cancellation from lightweight
modules. The generator and viewer share one controller registry; never create a
second instance or load the entire prompt builder just to abort a running request.
Retry execution loads within the permitted action and queue processing within the
verified member claim flow. Their failures release local pending state and leave
ordinary viewing available.

Claim URL helpers are independent of destination normalization. The trip area's
native `beforeLoad` prepares the optional recovery boundary only for the explicit
conflict marker, with navigation cancellation checked before and after loading.
The recovery dialog owns normalized creation prefills and renders complete native
links on its first visible render. Keep common trip views free of precomputing
creation links or importing recovery destination tables. Test both localized drafts
and keyboard focus with the shared dialog primitives.

## Foreground navigation and account home

The native router retains the current route presentation while destination loaders
and guards resolve (`defaultPendingMs: Infinity`). This is an explicit supported
TanStack policy, not a timer with an arbitrary long delay. Selective-SSR first
loads retain their existing document/pending fallback. The shared
`RouteNavigationFeedback` shows a visual progress fill from the router's
foreground pending status; preloads do not activate it. Do not announce fabricated numeric percentages or turn individual links into
competing loading state machines.

The URL adapter's NavLink derives active and pending styles from the requested
native location, so feedback does not wait for loader completion. TanStack still
owns anchor clicks, modified clicks, cancellation and redirects. The old content
can stay visible while its destination is highlighted.

`configurePageTransitions` enables native view transitions only for path changes,
checks the current reduced-motion preference on each navigation, and excludes
initial/query-only work. CSS supplies a 160ms crossfade with minimal movement and
a reduced-motion fallback. Unsupported browsers use ordinary native navigation.
Existing feature-specific transitions keep their own ownership.

The homepage is always public and never redirects a signed-in visitor. Its verified
member CTA points to the profile. General sign-in opens the shared modal directly
from Account/Konto and defaults to the profile through native navigation, without a
full document reload. Explicit guarded destinations and in-progress trip/creation
return URLs retain their complete query/hash semantics. The login page ignores
stale remembered marketing paths. Verified members keep the account dropdown; the
same button DOM survives hydration and session verification.

The top bar is one monotonic visual fill per foreground navigation, not a sliding
segment. Intermediate values are estimates and are not announced as percentages.
Actual completion fills 100%, holds briefly, then hides; repeated navigation and
unmount cancel the previous timers. Reduced motion removes interpolation. There
are no additional progress bars inside the initial marketing fallback. Auth
loading follows the presented native match, preserving a current public page when
an example is requested while still hiding private content on account replacement.

Trip presenters import their required TripView synchronously inside the native
route component chunk. Native component preloading therefore resolves the view
before the router commits. Do not wrap that required route view in another
React.lazy/Suspense waterfall. Optional embedded previews in creation keep their
separate lazy recovery. The account trip library can render while profile metadata
loads; only the personalized greeting waits for that data. ProfileHomeActions owns
compact actions; the retired private identity/statistics header stays removed.

ProgressiveImage retries the original source once if image optimization fails,
removing picture sources and srcSet for that attempt. The keyed resource lifecycle
handles events that finished before hydration and resets on a new source. Only an
original-source failure reaches the caller; there is no retry loop. The airplane
frame has the same one-retry policy while preserving its desktop-only picture source.
Navigation and authentication share an ownership-counted browser scroll lock;
opening the next overlay must not unlock a still-active overlay. Menu openers are
focused explicitly before mounting dialogs so Safari can restore keyboard focus.

Verification: blocked-loader navigation, superseding navigation, modified clicks,
preload isolation, reduced-motion policy, public home for verified members and profile-default sign-in and
private/public profile regressions, cold direct guest modal interaction, presented-route
auth isolation, required trip-view chunk delays and image-CDN failure recovery. See [TanStack navigation options](https://tanstack.com/router/latest/docs/guide/navigation)
and [router foreground state](https://tanstack.com/router/latest/docs/api/router/RouterStateType).

### Marketing notices

The header owns its sticky position. Language suggestions and translation notices
occupy normal document flow between the header and main content. MarketingNotice
owns intrinsic row/column reflow; dismissal removes its actual space. Do not add
fixed banner offsets, per-page top padding or JavaScript height measurements.
Keep long translated actions wrappable and check both LTR and RTL at narrow widths.

Public SSR date text must specify both locale and time zone. Release notes use
request-local language and the fixed-CET publication policy through the pure
releaseNotesFormat helper. Blog publication timestamps use UTC editorial dates.
Do not apply instant formatting blindly to nominal local-calendar festival dates.
Tests include a browser language differing from the route and a UTC+14 timezone.
