## Changes
- [x] [Fixed] 🪟 Loading placeholders no longer flash two or three times before a page appears. Opening a trip, and moving between pages, renders the same placeholder several times in quick succession behind the scenes; each one used to restart its animation from the beginning. They now carry on from where the last one left off, so you see one calm placeholder instead of a stutter.
- [x] [Improved] 🦴 Opening a trip now shows the shape of the trip page while it loads. Instead of a centred card that looked nothing like the planner, you see the day ruler, the row of cities and the map pane already sitting where they belong — so when the trip arrives it settles into place rather than replacing something else.
- [x] [Improved] 📱 On a phone the placeholder is the day sheet you actually get: the map behind it, the handle, the view buttons and the row of round day circles. For a trip you have opened on this device before, those circles already show its real dates, so nothing shifts when the trip finishes loading.
- [x] [Fixed] 🎚️ The day sheet no longer slides up twice when you open a trip on a phone. It used to play its opening slide once on arrival and then again a few seconds later, when the map finished starting up.
- [x] [Improved] 🌗 The loading placeholder is much calmer to look at. The old shimmer swept every block in lockstep at a hard contrast; the new one is a soft pass with a pause between each sweep, and it respects the reduce-motion setting on your device.
- [x] [Improved] 🧭 If you last had the map beside your timeline, the placeholder shows it beside your timeline — and the same for the map-on-top layout, including the pane widths you dragged. Your planner opens the way you left it, from the very first frame.
- [x] [Fixed] ⚡ Trips that open quickly no longer flash a placeholder at you. The skeleton now waits a moment before appearing, so a fast load goes straight to your itinerary.
- [ ] [Internal] 📐 Rebuilt the trip half of `AppBootstrapShell` against measured geometry from a live example trip at 1440×900: 76px header, 32px left gutter, 48px day columns, month band 0–31, day ruler 31–78, city row at 138 (h60, r8, 2px border). Verified by probing `.tf-boot-planner` in the running app during the Suspense window; every landmark lands on the real planner's offset. Transfer chips, leg lines and activity columns were built and measured too, then cut on request — the placeholder is the grid, the control clusters and the city row.
- [ ] [Internal] 🔁 Root cause of the flashing, measured in the running app: one navigation renders the shell as three separate DOM nodes inside 43ms — the `AppRoutes` Suspense fallback, the route component's own `!trip` branch, then the inner Suspense fallback for the lazy page — each a fresh element at a different tree position, so React cannot reuse the DOM and every CSS animation restarts at 0. The marketing side has the same shape via nested `AppRoutes`/`DeferredAppRoutes` boundaries: two placeholder headers 77ms apart on a plain route change. `services/appBootstrapShellEpoch.ts` tracks a loading *episode* (refcounted mounts, released 400ms after the last unmount) and the shell publishes `--tf-boot-epoch` / `--tf-boot-sweep-epoch`; the entrance delay becomes `calc(150ms - epoch)` and the sweep takes a negative delay off document time, so a remount resumes the animation's phase instead of replaying it. Measured after: epoch 0 → 33 → 40ms, fade delay 0.150s → 0.117s → 0.110s across the three nodes. The boundary nesting itself is untouched.
- [ ] [Internal] 🎞️ Replaced the `background-position` shimmer with a `.tf-bone` pseudo-element on a `translate3d` sweep (2.4s, 58% travel + hold, `--tf-bone-phase` for stagger) — the old one repainted a 200%-wide gradient per frame on the main thread. The map pane stays static on purpose. A single blended `mix-blend-mode: screen` band over the whole pane was tried first and rejected: it lifted the hairlines and borders too, so the structure dissolved mid-sweep.
- [ ] [Internal] ⏱️ `.tf-boot-planner` fades in via `animation: … 150ms both`, which holds it at `opacity: 0` through the delay rather than rendering and then hiding it.
- [ ] [Internal] 🗺️ `TripRouteLoadingShell` reads `readPersistedTripViewSettings()` directly in render (no hook — it is a Suspense fallback, and `React.useState` on the namespace import throws under `preact/compat` here) and passes `layoutMode` / `sidebarWidth` / `timelineHeight` down as `data-tf-boot-layout` and CSS custom properties.
- [ ] [Internal] 📱 Phone placeholder mirrors `TripMobilePlannerShell`: a sheet at the `half` snap (`max(168px, 58%)`, the same floor and fraction the shell uses) with the map pulled up by the same 28px underlap. Measured against the live shell on a 375×812 viewport: sheet 436px at y=376, map ending at 404, day bubble 48px — identical to the real one. Both layouts ship in the markup and the stylesheet picks, rather than measuring the viewport in JS and risking a wrong first frame.
- [ ] [Internal] 📅 `services/tripRouteShellPreview.ts` reads the trip out of local storage by route id and derives the strip's dates from `getTripSpan`. Memoised per trip id including misses, because `getTripById` parses the whole store and the shell renders two or three times per navigation. Returns null for shared and example trips, where the placeholder falls back to grey circles. A stale cached trip would briefly show its old dates — the window is the few hundred milliseconds before the real trip renders.
- [ ] [Internal] 🎚️ `TripMobilePlannerShell` measured its container in a passive effect, so the sheet painted at the 168px PEEK floor and then transitioned up to its real height — an opening slide nobody asked for. Moved to `useLayoutEffect` and gated the height/bottom transitions on a new `isHeightAnimated` flag that is cleared on any layout-driven resize and restored a frame later, so only a snap or a drag animates. Measured before: `168 → 436 → 168 → 436`, two slides. After: a single `436`.
- [ ] [Internal] ⚠️ Root cause of the second slide, left unfixed and worth its own change: `MapRuntimeProvider` renders `children` bare while disabled and wrapped in `<APIProvider>` once enabled, so when `useDeferredMapBootstrap` flips at its 4s ceiling the children are re-parented and **React unmounts and remounts the entire planner**. Confirmed in the running app: new sheet and map-pane nodes at t=4250ms, immediately before the map mounts. Every bit of planner state goes with it — the sheet's snap, the selected day, scroll position, timeline zoom — so tapping a day inside the first four seconds is silently undone. The fix is to stop re-parenting: `APIProvider` needs to wrap only what consumes Google Maps context (`ItineraryMap` and `DetailsPanel`), not the whole planner. Not attempted here because it is a map-provider refactor on a PR about a loading placeholder.
- [ ] [Internal] 🧹 Dropped the dead trip-body rules (`tf-boot-page--trip`, `tf-boot-trip-summary`, `tf-boot-trip-canvas`, `tf-boot-card`, `tf-boot-metric`, `tf-boot-surface`) and the `tf-boot-shimmer` keyframes; marketing chrome bones now share `.tf-bone`. Coverage in `tests/browser/tripview/tripRouteLoadingShell.browser.test.ts`, `tests/browser/tripview/tripRouteShellPreview.browser.test.ts` and `tests/browser/bootstrap/appBootstrapShellEpoch.browser.test.ts`; `tests/unit/indexBootstrapShell.test.ts` updated for the new class strings.
